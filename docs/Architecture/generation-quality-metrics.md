# 生成质量量化指标体系（generation-quality-metrics）

依据：V25-D-26/27/28（密度制、SPEC/USER 双区块注入、rubric 纯观测口径）。本文是制卡质量
量化评估的唯一指标权威；数据源全部来自现有落库（`cards` 评分五字段、`knowledge_points`、
`batches` 质量观测列、`llm_call_attempts` 账本），不新造数据。评估入口：
`conda run -n shanka-backend python scripts/task_quality_report.py --task-id <task_id>`。

## 指标分组

### A 质量组（数据：cards 评分五字段 / §6.9 quality-summary）

| 指标 | 定义 | 初始参考值* | 支撑的决策 |
| --- | --- | --- | --- |
| A1 四维均分 | evidence/correctness/difficulty/learning_value 各 0-3 | ≥2.5 健康；2.0-2.5 观察；<2.0 干预 | 定位提示词短板：哪一维弱改哪段 prompt |
| A2 总分分布 | rubric_total P50 / P25（服务端计算，0-12） | P50≥9；P25≥7 | P50 看水位，P25 看下限稳定性 |
| A3 低分占比 | rubric_total ≤ 4 的卡占比 | <10% | **>10-15% 即为"低分自动重生成门禁"的立项依据**（V25-D-28 的决策输入） |
| A4 评分覆盖率 | 已评分卡 / 已生成卡 | 100% | <100% 说明 SCORING 链路有失败 |

### B 编排组（数据：knowledge_points / batches / tasks.cursor）

| 指标 | 定义 | 初始参考值* | 支撑的决策 |
| --- | --- | --- | --- |
| B1 配额利用率 | 实际单元数 / 区间上界合计，按难度分列 | 60%-120% | 密度锚点 6/12/20 的核心校准环：持续 <60% = Planner 认为内容撑不起（考虑降锚点）；持续贴 120% 被截 = 锚点保守 |
| B2 难度偏差 | 每难度实际单元占比 - 目标占比（pp） | ≤10pp | 难度比例传导是否失真 |
| B3 内容覆盖率 | 被单元引用的 chunk 数 / 章节有效 chunk 数 | ≥60% | Planner"偷工"检测（只挑容易段落）；基于 `source_chunk_ids` 聚合 |
| B4 重复率 | batches.duplicate_rate 均值 | <5% | 指纹去重有效性 |

### C 效率/成本组（数据：llm_call_attempts 账本，§8.4 权威）

| 指标 | 定义 | 当前基线（2026-08-31，n=3） | 支撑的决策 |
| --- | --- | --- | --- |
| C1 每卡调用数 | (生成 + 评分) / 卡 | ≈2 | 成本模型 |
| C2 每卡墙钟 | 任务时长 / 卡 | 7.7s（3 卡小任务） | 大章任务后重测 → 全书任务时长推算 |
| C3 重试率 | attempt_no > 0 的尝试占比 | 0% | <15% 健康；prompt/schema 稳定性 |
| C4 每卡成本 | tokens × 单价（§8.4 价格常量） | 首个密度制任务后填 | 全书单任务 vs 分章的预算决策 |

### D 可靠性组

| 指标 | 定义 | 参考值 | 说明 |
| --- | --- | --- | --- |
| D1 任务成功率 | COMPLETED / 终态任务 | ≥90% | 剔除环境故障期（如 8/28-29 API Key 未配置）口径 |
| D2 失败阶段分布 | 按首次失败 stage 统计 | — | 历史最弱环节为样卡阶段 |
| D3 样卡→正式转化率 | start 的任务 / 到过 AWAITING 的任务 | — | 产品漏斗观测 |

## 校准纪律

1. **初始参考值为经验设定，不具备统计效力**（基线 n=3，全部总分 ≥10）。首批密度制任务
   累计 ≥50 张卡后，用真实分布修订一次全部参考值；此后每累计 100 张复核。
2. 参考值修订必须在本文件留痕（日期 + 样本量 + 旧值 → 新值 + 依据任务 ID）。
3. Rubric 评分为纯观测（V25-D-28），任何指标都不构成生成结果的自动门禁；B5 验收门禁
   只含客观可判定项（数量区间、难度分布偏差、任务终态、评分覆盖率）。

## 外部双裁判盲评协议（裁判可靠性校验，非生产链路）

目的：检验生产评分（DeepSeek 自评）的可信度——LLM 自评存在自我偏好虚高风险。

- **执行者**：主 agent 在评估时点开启 ≥2 个干净上下文 subagent 盲评（不进生产流水线、
  不进 CI、不替代 SCORING 阶段）。
- **协议**：
  1. 主 agent 预取每张卡的 front/back/目标难度/卡型 + 对应 `source_chunk_ids` 原文，
     内联进 subagent 提示词（自包含，subagent 不碰数据库）；
  2. rubric v3 全文原样下发（同一把尺子，分数可比）；
  3. 盲评：不告知 DeepSeek 已打的分（防锚定）；逐卡独立评四维 0-3；
  4. subagent 只输出逐卡四维分数 JSON，总分由主 agent 按服务端同口径计算；
  5. 验收任务 ≤24 张 → 2 个 subagent 各评全部卡（+DeepSeek 共三方）；更大任务按难度
     分层抽 30 张。
- **产出**：双裁判对比报告——每维完全一致率 / ±1 率 / 均值差，系统性偏差标记
  （如 DeepSeek evidence 均值显著高于外部 → 虚高结论）。
- **边界**：第二裁判回答"DeepSeek 的分数可信吗"，不回答"卡片到底好不好"；终审仍是
  人工抽检。偏差结论只对"当前 rubric + 当前模型"有效，prompt 升版或换模型后重跑。

### 双裁判盲评对比报告（2 × 干净上下文 subagent，rubric v3 原文，盲评 18/18）

裁判间一致性（A vs B）：

| 维度 | 完全一致 | ±1 | 均值差 |
| --- | --- | --- | --- |
| evidence | 17/18 (94%) | 18/18 | -0.06 |
| correctness | 18/18 (100%) | 18/18 | 0.00 |
| difficulty | 18/18 (100%) | 18/18 | 0.00 |
| learning_value | 14/18 (78%) | 18/18 | 0.00 |

裁判 vs DeepSeek 自评（均分，n=18）：

| 维度 | 裁判 A | 裁判 B | DeepSeek | 裁判-DS |
| --- | --- | --- | --- | --- |
| evidence | 2.83 | 2.89 | 2.83 | +0.03 |
| correctness | 2.89 | 2.89 | 2.72 | +0.17 |
| difficulty | 1.83 | 1.83 | 2.39 | **-0.56** |
| learning_value | 2.67 | 2.67 | 2.50 | +0.17 |

系统性偏差标记：

1. **难度维虚高（最重要）**：两个独立裁判在 11 张"复述型卡"上集中给 1，DeepSeek 给 2-3
   （均分差 -0.56）。DeepSeek 自评对"照抄/关键词即可作答"不敏感，难度匹配观测应以外部
   裁判口径为主。
2. **单卡极性反转**：卡 `0c337b25` 双裁判一致满分（3,3,3,3），DeepSeek 给 2,0,1,1
   （总分 4，其全任务最低）；卡 `7e4ff591` 双裁判独立给出 evidence=1/correctness=1
   （来源薄），DeepSeek 给 3,3,3,3（总分 12）。DeepSeek 自评存在与内容无关的极端误判，
   低分自动重生成门禁（若未来引入）不得以单次自评为据。
3. learning_value 裁判间 78% 一致为最"软"维度，其余三维裁判间 ≥94% 一致。

结论（只对当前 rubric v3 + deepseek-v4-flash 有效）：生产自评分数的**相对排序**大体可用
（最低分卡 7e4ff591 确为裁判公认最弱），但**绝对分不可信**（难度维系统性虚高 + 随机极性
误判）。人工抽检优先级：先抽 DeepSeek 判 ≤8 或 ≥12 的两端卡。
