## 1. 架构目标与边界

V2.5 在现有账号、PDF、生成、牌组、FSRS 和统计能力之上增加四个稳定边界：

1. `LearningProject` 成为 PDF、章节、牌组和任务的聚合根；
2. 制卡任务拆成可持久化草稿、样卡确认和正式生成，并采用整批发布；
3. `UserPreferences` 和 `ProjectStudySettings` 成为跨设备学习配置权威；
4. 删除撤销、AI 重写预览和统计去重在服务端建立可恢复事务语义。

不在 V2.5 引入消息队列、微服务、事件总线、通用 Repository 基类或第二套 ORM。后台任务继续使用现有执行器；
SQLite 继续作为当前数据库，所有新增状态机必须能在单库事务内证明正确。

## 2. 聚合与依赖关系

```text
User
├── UserPreferences ── current_project_id ──┐
├── LearningProject                         │
│   ├── PdfFile                             │
│   ├── Chapter                             │
│   ├── ProjectStudySettings                │
│   ├── Deck ── Card ── ReviewState         │
│   └── GenerationTask ── staged Card       │
├── independent Deck ── Card                │
├── CardDeletionBatch ── pending Card       │
├── CardRewritePreview                      │
└── ReviewEvent / AuthSession / ApiKey ─────┘
```

- 一个项目恰好对应一份当前 PDF；解析失败时允许原子替换该 PDF。
- 一个项目可有多个牌组和多个制卡任务；任务目标牌组必须属于同一项目。
- `Deck.project_id = null` 表示独立牌组。
- `Card.chapter_id = null` 表示“未归属章节”，不是另建伪章节行。
- 任务生成卡在成功前为 `STAGED`，所有普通卡片查询必须只返回 `PUBLISHED`。

## 3. 目标资源模型

### 3.1 AuthUser 与 UserPreferences

`AuthUser` 在现有字段上增加：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `email` | string | 只读返回规范化后的当前登录邮箱 |
| `avatar_key` | enum | `mood_01`～`mood_12`，只接受内置预设 |

`UserPreferences`：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `default_coverage_mode` | enum | `COMPACT / BALANCED / EXTENSIVE`，默认 `BALANCED` |
| `default_difficulty_ratio` | object | `basic/understanding/deep_question` 为 0～100 的 10% 整数档，合计 100 |
| `daily_learning_goal` | int | 旧账号兼容偏好；新项目计划不再使用该单一目标 |
| `learning_timezone` | string | 有效 IANA 时区，账号级权威 |
| `current_project_id` | uuid/null | 当前学习项目；项目删除时置空 |
| `updated_at` | datetime | 最后成功保存时间 |

主题仍为客户端本机偏好，不进入此资源。

### 3.2 LearningProject

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `project_id` | uuid | 用户内资源标识 |
| `name` | string | 去首尾空白后 1～60 字符，可重名 |
| `file` | PdfFile | 当前 PDF；列表响应可只返回摘要 |
| `status` | enum | `PARSING / PARSE_FAILED / AWAITING_CHAPTER_CONFIRMATION / READY` |
| `chapter_count` | int | 派生 |
| `deck_count` | int | 派生 |
| `task_count` | int | 派生 |
| `created_at/updated_at/version` | - | 缓存刷新与并发检查 |

默认名称取上传文件名去扩展名。`status` 由 PDF 状态与 `chapters_confirmed_at` 确定，不建立可漂移的第二套状态列。

### 3.3 ProjectStudySettings

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `project_id` | uuid | 一项目一行 |
| `selected_new_card_chapter_ids` | uuid[] | 只限制新卡；空数组表示暂无新卡范围 |
| `include_unassigned` | bool | 是否包含 `chapter_id = null` 的新卡 |
| `updated_at` | datetime | |

### 3.4 GenerationTask

用户状态统一为：

```text
DRAFT
  → SAMPLE_GENERATING
  → AWAITING_SAMPLE_CONFIRMATION
  → GENERATING
  → COMPLETED | FAILED

DRAFT | SAMPLE_GENERATING | AWAITING_SAMPLE_CONFIRMATION → ABANDONED
FAILED → 创建 retry_of_task_id 指向原任务的新任务
```

目标字段：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `task_id/project_id/file_id/deck_id` | uuid | 新任务均必填并做同项目归属校验；迁移前已失去 PDF 的终态历史任务可返回 null project/file |
| `retry_of_task_id` | uuid/null | 只指向同用户失败任务 |
| `status` | enum | 上述七态 |
| `internal_stage` | enum/null | `PLANNING / GENERATING / SCORING / PUBLISHING`，不直接作为用户状态 |
| `selected_chapters` | Chapter[] | 开始正式生成前冻结快照 |
| `generation_config` | GenerationConfig | 任务独立配置 |
| `sample_cards` | SampleCard[] | 持久化 1～3 张；配置变化时清空 |
| `sample_config_hash` | string/null | 防止确认过期样卡 |
| `sample_confirmed_at` | datetime/null | |
| `generated_card_count` | int | 只统计已发布卡；失败任务为 0 |
| `error_code/failure_stage` | string/enum | 用户安全错误 |
| `created_at/started_at/ended_at/updated_at` | datetime | |

删除任务默认只删历史：已发布卡的 `source_task_id` 置空；选择同时删除结果时才删除该任务的已发布卡及复习数据。
失败任务的 `STAGED` 卡在删除任务时级联清理，绝不能转为无来源可见卡。

### 3.5 GenerationConfig 与 Planner

```json
{
  "coverage_mode": "BALANCED",
  "difficulty_ratio": {
    "basic": 40,
    "understanding": 40,
    "deep_question": 20
  },
  "custom_requirements": ""
}
```

- 比例使用整数百分比，允许任一档为 0；旧 `application` 在 API 和资产新版本中改为 `deep_question`，
  数据迁移把历史 `APPLICATION` 映射为 `DEEP_QUESTION`。
- Planner 输出来源锚定的候选学习单元并标注 `CORE / IMPORTANT / LOW_FREQUENCY` 覆盖层级；代码按覆盖模式
  选择允许层级并施加与模式无关的安全硬上限，不用“凑够 N 张”驱动模型。
- `COMPACT` 只选核心，`BALANCED` 选核心与重要支撑，`EXTENSIVE` 可选全部有独立价值的候选；知识过少时
  Planner 可产生不同学习角度，但必须有不同学习目标，禁止同义重复。
- 代码根据最终合法单元数和难度比例确定性分配难度；比例为 0 的难度不生成单元和样卡。
- `DEEP_QUESTION` 只允许 `QUESTION`，背面使用参考思路；判断题只属于前两档。

### 3.6 Deck 与 Card

`Deck` 增加 `project_id: uuid/null`。`Card` 增加：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `source_task_id` | uuid/null | 生成来源任务；删历史并保留卡时置空 |
| `chapter_id` | uuid/null | null 在项目内显示“未归属章节” |
| `publication_state` | enum | `STAGED / PUBLISHED`；普通查询只返回后者 |
| `delete_batch_id` | uuid/null | 非空表示 10 秒待删除，普通查询隐藏 |
| `pending_delete_at/undo_until` | datetime/null | 服务端计时 |
| `target_difficulty` | enum/null | `BASIC / UNDERSTANDING / DEEP_QUESTION`；手动/导入为 null |

卡片可见条件为 `publication_state = PUBLISHED AND delete_batch_id IS NULL`。所有列表、到期队列、计划和统计
复用同一个查询谓词，禁止各模块自行漏写过滤条件。

### 3.7 CardDeletionBatch

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `delete_batch_id` | uuid | 用户内标识 |
| `card_ids` | uuid[] | 服务端返回；数据库以 Cards 外键关系为权威 |
| `undo_until` | datetime | 服务端接受最后一次追加后 10 秒 |
| `status` | enum | `PENDING / UNDONE / FINALIZED` |
| `created_at/updated_at` | datetime | |

向仍为 `PENDING` 的批追加卡时，服务端原子更新整批 `undo_until = now + 10s`。撤销在同一事务清空所有卡片
删除标记。过期批由后台清理器或任意相关读取前的惰性清理最终硬删除；两种路径必须幂等。

### 3.8 CardRewritePreview

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `rewrite_id/card_id` | uuid | |
| `base_card_version` | string | 应用时乐观并发校验 |
| `front/back/card_type/target_difficulty` | - | 预览内容 |
| `custom_requirements` | string/null | 不保存完整 Prompt |
| `status` | enum | `PENDING / APPLIED / CANCELLED / EXPIRED` |
| `expires_at` | datetime | 建议 24 小时；实现常量统一 |

只允许来源项目、PDF、章节和来源页仍存在的 `GENERATED` 卡创建预览。应用时同事务更新卡片、递增版本并
重置 ReviewState；版本已变化返回 `409 CARD_VERSION_CONFLICT`，原卡不变。

### 3.9 TodayStudyPlan 与 StatsDashboard

`TodayStudyPlan` 至少返回：账号学习时区、学习日期、当前项目摘要、每日新学/巩固目标、今日去重完成数、到期总数、
主计划剩余数、积压数及有序卡片列表。项目计划由卡组关联表与双目标保存。

主计划：

1. 当前计划所选卡组中已学习且到期的可见卡，最多取每日巩固目标；
2. 按 `遗忘风险 DESC → 逾期时长 DESC → card_id` 稳定排序；
3. 再从相同卡组范围的 `NEW` 卡最多取每日新学目标；
4. 同一 `(账号学习日期, card_id)` 只增加一次今日完成。

遗忘风险由统一 FSRS 适配器按服务端 `now` 计算；无法计算时风险置 0，再按逾期与稳定键排序。

`StatsDashboard` 不再接收客户端 `timezone` 或 `weekly_goal`。服务端读取 `UserPreferences`：

- 周活动仍统计成功评级事件数；
- 项目周目标为（每日新学目标 + 每日巩固目标）× 7；账号总体看板仍保持现有全局活动口径；
- 周完成数为本周不同 `(账号学习日期, card_id)` 数；
- 时区改变后用 UTC `reviewed_at` 重新分桶，不改写事件；
- `review_events.device_timezone` 降级为可空审计字段，不参与权威统计。

## 4. HTTP 目标契约

所有业务路径继续使用 `/v1` 前缀和 Bearer 鉴权。除明确的只读、登录和无副作用预览生成外，写请求携带
`Idempotency-Key`。下表是 V2.5 必须写入 `openapi.yaml` 的目标接口集合。

### 4.1 账号与设置

| 方法 | 路径 | 关键语义 |
| --- | --- | --- |
| GET | `/auth/me` | 返回含 email、avatar_key 的 AuthUser |
| PATCH | `/auth/me` | `{username?, avatar_key?}`，至少一个字段 |
| GET | `/preferences` | 返回 UserPreferences |
| PATCH | `/preferences` | 部分更新；比例、目标、IANA 时区服务端校验 |

### 4.2 学习项目与章节

| 方法 | 路径 | 关键语义 |
| --- | --- | --- |
| POST | `/projects` | multipart PDF + 可选 name；上传成功即建立项目 |
| GET | `/projects` | 当前用户项目列表，支持真实空态 |
| GET/PATCH | `/projects/{project_id}` | 详情或重命名 |
| DELETE | `/projects/{project_id}?retain_decks=true|false` | 活跃状态保护；按选择保留或删除全部项目牌组 |
| POST | `/projects/{project_id}/replace-pdf` | 仅解析失败项目可替换并重新解析 |
| PATCH | `/projects/{project_id}/chapters/{chapter_id}` | 修改章节 |
| DELETE | `/projects/{project_id}/chapters/{chapter_id}?delete_cards=false` | 活跃任务保护；保留卡时 chapter_id 置空 |
| POST | `/projects/{project_id}/confirm-chapters` | 确认目录，使项目进入 READY |
| GET/PATCH | `/projects/{project_id}/study-settings` | 新卡章节范围与未归属分组 |

旧 `/pdfs` 路径在开发过渡期可保留，但 V2.5 Release 客户端只使用项目接口；兼容端点不得创建第二份业务语义。

### 4.3 制卡任务

| 方法 | 路径 | 关键语义 |
| --- | --- | --- |
| POST | `/projects/{project_id}/tasks` | 建立 DRAFT，保存章节、目标牌组和配置 |
| GET | `/tasks?project_id=&status=` | 学习页任务区和历史列表 |
| GET/PATCH | `/tasks/{task_id}` | 读取；仅 DRAFT/AWAITING_SAMPLE_CONFIRMATION 可改配置，修改后样卡失效 |
| POST | `/tasks/{task_id}/samples` | 持久化生成 1～3 张样卡；防重复触发 |
| POST | `/tasks/{task_id}/start` | 校验样卡 hash 后进入 GENERATING |
| POST | `/tasks/{task_id}/abandon` | 只允许正式生成前状态 |
| POST | `/tasks/{task_id}/retry` | 失败任务创建关联新任务；正式生成失败可沿用已确认样卡 |
| DELETE | `/tasks/{task_id}?delete_generated_cards=false` | 终态任务；按参数保留或删除已发布卡 |

删除用户侧 `/resume`、`/cancel`、暂停状态和按钮。执行器内部恢复不是用户 API，孤儿任务通过同一状态的租约/心跳
重新抢占，不暴露 `PAUSED`。

### 4.4 牌组、卡片与撤销

| 方法 | 路径 | 关键语义 |
| --- | --- | --- |
| GET/POST | `/decks` | 支持 `project_id` 归属；手动独立牌组 project_id=null |
| GET/PATCH/DELETE | `/decks/{deck_id}` | 删除时服务端自动取消活跃任务并级联清理卡片 |
| GET/POST | `/decks/{deck_id}/cards` | GET 支持 order、content_difficulty、mastery 过滤 |
| PATCH | `/cards/{card_id}` | 编辑后重置 ReviewState |
| DELETE | `/cards/{card_id}?delete_batch_id=` | 返回 CardDeletionBatch，不立即硬删 |
| GET | `/card-deletion-batches/pending` | App 重启恢复仍有效的撤销批次 |
| POST | `/card-deletion-batches/{delete_batch_id}/undo` | 恢复整批 |
| POST | `/cards/{card_id}/rewrite-previews` | 生成并持久化预览，不改原卡 |
| POST | `/cards/{card_id}/rewrite-previews/{rewrite_id}/apply` | 版本一致时原子替换 |
| DELETE | `/cards/{card_id}/rewrite-previews/{rewrite_id}` | 取消预览，可幂等 |

自由刷题筛选：`order=position|random`；`content_difficulty=BASIC|UNDERSTANDING|DEEP_QUESTION|UNLABELED`；
`mastery=all|mastered|unmastered`。随机顺序由客户端会话 seed 固定，服务端不得每翻一张重新洗牌。

### 4.5 学习、复习和统计

| 方法 | 路径 | 关键语义 |
| --- | --- | --- |
| GET/PUT | `/study/plan` | 原子读取/保存当前项目、选中卡组和新学/巩固双目标 |
| GET | `/study/today` | 当前项目今日计划；服务端账号时区和去重 |
| GET | `/decks/{deck_id}/review` | 独立牌组或指定牌组到期复习 |
| GET | `/study/today/backlog` | 分页读取超过巩固软目标的到期积压卡 |
| POST | `/review-events` | 不再要求 device_timezone；返回更新 ReviewState 和本次学习日期 |
| GET | `/stats/dashboard` | 无 timezone/weekly_goal 查询参数 |

## 5. 数据库目标迁移

V2.5 使用一个新的不可逆 Alembic revision；迁移必须从运行时真实 head 生成，不预写 revision ID。升级前备份数据库，
downgrade 继续 fail-closed。不得清空 V2.4 用户数据；迁移规则如下。

### 5.1 新表

| 表 | 关键列与约束 |
| --- | --- |
| `learning_projects` | `project_id PK, user_id FK, file_id UNIQUE FK, name, chapters_confirmed_at, version, timestamps`; index `(user_id, updated_at)` |
| `user_preferences` | `user_id PK/FK, coverage_mode, basic_ratio, understanding_ratio, deep_question_ratio, daily_goal, learning_timezone, current_project_id FK SET NULL, updated_at`;比例 CHECK |
| `project_study_settings` | `project_id PK/FK CASCADE, selected_chapter_ids JSON, include_unassigned, daily_new_goal, daily_review_goal, updated_at` |
| `project_study_decks` | `project_id + deck_id PK/FK CASCADE, created_at`; index `(deck_id)`；保存今日计划选中的项目卡组 |
| `card_deletion_batches` | `delete_batch_id PK, user_id FK, status, undo_until, timestamps`; index `(user_id,status,undo_until)` |
| `card_rewrite_previews` | `rewrite_id PK, user_id/card_id FK, base_card_version, preview JSON, custom_requirements, status, expires_at, timestamps`; index pending expiry |

### 5.2 现有表新增或调整

- `users`: 新增 `avatar_key NOT NULL DEFAULT 'mood_01'`；email 已存在。
- `pdf_files`: 新增解析短租约 `parse_lease_token/parse_lease_until` 与 `parse_version`；新增
  `project_id UNIQUE FK learning_projects` 的循环关系不可取，以 `learning_projects.file_id`
  为唯一外键权威，PDF 表不重复存 project_id。删除/替换递增版本使迟到解析结果失效。
- `decks`: 新增 `project_id NULL FK learning_projects ON DELETE SET NULL`；source 枚举补 `GENERATED`。
- `tasks`: 新增 `project_id NULL FK`（新写入应用保证必填，NULL 只兼容迁移前已失去 PDF 的终态任务）、
  `retry_of_task_id NULL FK SET NULL`、样卡 JSON/hash/确认时间；状态迁移：
  `PENDING→DRAFT`、`RUNNING→GENERATING`、`COMPLETED→COMPLETED`、`FAILED→FAILED`、`CANCELLED→ABANDONED`；
  历史 `PAUSED` 迁为 `FAILED` 并写 `LEGACY_PAUSED_TASK`，禁止留下 V2.5 不可表达状态。
- `cards`: 新增 `source_task_id NULL FK tasks SET NULL`、`chapter_id NULL FK chapters SET NULL`、
  `publication_state NOT NULL DEFAULT PUBLISHED`、删除批次/时间字段；历史卡均迁为 PUBLISHED。
- `review_events.device_timezone`: 改为可空审计字段；不删除历史值。

`learning_projects` 与既有 PDF 的回填：每个现有 PDF 建一个项目，名称取 filename 去扩展名；PARSED 项目默认
`chapters_confirmed_at = migrated_at`，其他按 PDF 状态映射。既有 generated deck 若能从 task.file_id 唯一定位项目则
绑定；无法唯一定位的牌组保持独立。现有 task 绑定其 file 对应项目；`file_id = null` 的既有终态任务保留为只读
历史且不可重试。迁移报告必须记录无法归属的牌组/任务数量。

### 5.3 原子事务

必须在同一事务完成：

- 正式任务成功：校验至少一张合法 STAGED 卡 → 全部改 PUBLISHED → task COMPLETED/count 更新；
- 任意正式阶段失败：task FAILED，STAGED 卡继续隔离；
- 项目删除：retain 选择对应 detach 或 delete，服务端自动取消活跃任务并使解析/worker 租约失效
  → 删除 PDF/章节/任务/项目；
- 卡片删除批追加、撤销和最终清理；
- 重写预览应用：版本 CAS → 卡片正文更新 → ReviewState 重置 → preview APPLIED；
- 评级：ReviewEvent 插入 → ReviewState 更新；今日/周完成动态聚合，不另存易漂移计数。

## 6. 错误码增量

| 错误码 | HTTP | 使用场景 |
| --- | --- | --- |
| `PROJECT_NOT_FOUND` | 404 | 项目不存在或跨用户 |
| `PROJECT_STATE_CONFLICT` | 409 | 当前项目状态不允许操作 |
| `PROJECT_HAS_ACTIVE_TASK` | 409 | 仅旧兼容入口或并发状态冲突；项目/牌组确认删除默认自动取消活跃任务 |
| `TASK_STATE_CONFLICT` | 409 | 状态迁移非法 |
| `TASK_ZERO_CARDS` | 422 | 正式生成无有效卡 |
| `SAMPLE_STALE` | 409 | 配置变化后仍尝试确认旧样卡 |
| `INVALID_LEARNING_TIMEZONE` | 400 | 非法 IANA 时区 |
| `INVALID_PREFERENCES` | 400 | 比例或每日目标非法 |
| `CARD_DELETE_WINDOW_EXPIRED` | 409 | 撤销窗口已过 |
| `CARD_REWRITE_UNAVAILABLE` | 409 | 来源已失效或非生成卡 |
| `CARD_VERSION_CONFLICT` | 409 | 预览基于旧版本 |

错误响应继续使用统一 `error.code/message/localization_key`，不得返回 SQL、Prompt、Key 或内部状态栈。

## 7. Agent 资产与 AI 质量

非视觉实施必须新建资产版本而非原地修改：

- Planner schema 增加覆盖层级、来源 chunk、学习目标和不同角度标识；
- Planner prompt 使用核心/重要支撑/低频独立知识的语义，不出现目标卡数或数量区间；
- Generator 把 `DEEP_QUESTION` 限定为问答卡，背面为参考思路；
- Rubric 继续记录来源、正确性、难度、学习价值，并补同义重复审查夹具；
- 更新 `manifest.json` 与 CHANGELOG 后，同步 structure-contract 中的实际版本号；在资产文件真正存在前不得预写版本。

代码负责状态、ID、比例、确定性分配、硬上限和事务；LLM 只提供来源锚定的语义候选与卡片内容。

## 8. Android 分层与双 Agent 文件边界

由于现有 `AppViewModel.kt` 同时包含 Mock、网络编排和 UI 状态，V2.5 先拆出稳定桥接层：

```text
data/remote/v25/       # DTO、HTTP client、Repository 实现（非视觉 Agent）
domain/v25/            # Repository 接口、UI 无关模型（非视觉 Agent）
ui/v25/                # Screen、Component、UI state mapping（视觉 Agent）
ui/navigation/         # Route 与导航呈现（视觉 Agent）
```

- 非视觉 Agent 不修改 `ui/v25/**`、主题、drawable、截图或布局；
- 视觉 Agent 不修改 `data/remote/v25/**`、后端、迁移、OpenAPI、Gradle 环境地址或签名；
- `AppViewModel.kt` 由视觉 Agent 负责移除 Mock 并组合 Repository；非视觉 Agent 只通过新增接口提供能力；
- 如必须改变桥接接口，先修改 `domain/v25/**` 并通知另一 Agent，不得双方同时编辑同一文件；
- Release 中 `FrontendTestFixtures`、`FRONTEND_TEST_MODE` 和 `BuiltinDecks` 不可达或移除；Debug 可保留独立 fixture，
  但不得通过账号或 Release 构建启用。

## 9. Release 构建契约

- `debug` 可配置本机/测试地址；`release` 的 base URL 为构建期固定正式 HTTPS 地址，UI 不提供覆盖入口；
- Release 运行时不依赖 `res/` 样书、DiceBear 网络、开发机文件或 Debug 日志；12 个 Moods 头像作为 APK 本地资源；
- 输出固定为仓库根 `releases/app-release.apk`，成功构建后原子覆盖；失败不改动旧文件，并在报告标识失败；
- APK 不入 Git；签名凭据只由安全的本机/CI 环境输入；
- `versionName=2.5.0`，`versionCode` 高于已安装版本；生成 SHA-256、签名和目标设备安装证据。
