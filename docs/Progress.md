## 2. 开发顺序(依赖驱动)

```text
Phase 0 基础设施 ──→ Phase 1 牌组/复习/看板 ──→ Phase 2 PDF 制卡 ──→ Phase 3 收尾
     │                        │                     │
     └────────────────────────┴──── P2-1 API Key ────┘
```

排期逻辑:

- **Phase 1 先行**:牌组、卡片、复习、看板的前端已有本地实现,是联调收益最快的模块;FSRS 集成风险集中在 P1-3,尽早暴露。
- **Phase 2 居中**:PDF 制卡是核心链路但最长,依赖 P2-1(API Key)与 P2-2(PDF 解析),与 Phase 1 可部分并行。
- **Phase 3 收尾**:单卡重写复用 Phase 2 的 Schema/Rubric 设施,最后做;验收回归放最后。
