# V2.5 模块 PRD：Release 与跨模块验收

| 文档属性 | 内容 |
| --- | --- |
| 所属版本 | v2.5.0 |
| 模块状态 | 已确认 v1.0 |
| 发布对象 | Android APK |
| 模块目标 | 将现有 Debug/演示状态收敛为可安装、可持续使用、可证据化验收的正式版本 |

---

## 1. Release 定义

V2.5 的“正式版本”仅指 Android Release APK，不包含 iOS、桌面端、网页端或应用商店上架。

正式交付物：

```text
/home/kbzz1/shanka_backend/releases/app-release.apk
```

业务规则：

- 每次生成新的正式 APK 固定覆盖该路径；
- APK 不提交 Git；
- `versionName` 为 `2.5.0`；
- `versionCode` 必须高于此前可安装版本；
- APK 必须使用正式签名，可在目标 Android 设备完成安装和升级；
- Release 固定连接正式后端，普通用户不能修改服务器地址；
- Debug 才允许连接本机或测试环境。

`res/` 继续用于样书和只读验收资源，不作为 APK 正式输出目录。

## 2. Release 清理要求

### V25-REL-FR-01 真实数据

- 删除内置演示牌组、Mock 卡片和 Mock 用户资料；
- 首页、牌组、学习、任务和统计全部使用真实账号数据；
- 空账号展示真实空态，不自动注入样例内容；
- 统计页不显示固定柱状图、固定连续天数、固定百分比或随机数。

### V25-REL-FR-02 Debug 与死入口

- 删除或隐藏 Debug、测试平台、环境切换、日志查看和演示入口；
- 未开发完成的按钮、菜单和页面在 Release 中不展示；
- 不出现“未构建”“敬请期待”“占位页面”或点击无反应的可见入口；
- 不以固定成功 Toast、伪任务完成或本地硬编码结果替代服务端行为；
- 当前头像错误进入登录页、暂停任务、服务器地址编辑等旧行为必须被替换或隐藏。

### V25-REL-FR-03 构建分离

- Debug 与 Release 使用明确区分的环境配置；
- Release 产物中不得包含可被普通用户触达的本机地址配置；
- Release 不依赖开发机文件、DiceBear 网络接口、样书路径或 Mock 服务才能启动；
- 生产密钥、签名密码、DeepSeek API Key 和 `.env` 不写入仓库、APK 可读资源、日志或报告；
- 构建失败不得保留旧 APK 并将其报告为本次新产物。

## 3. 跨模块用户主链路

正式发布前必须在全新或已清除数据的目标 Android 设备上走通：

1. 安装 v2.5.0 Release APK；
2. 注册或使用邮箱与密码登录；
3. 打开个人主页，查看邮箱，修改昵称并切换 Moods 预设头像；
4. 新建学习项目并上传具有文本层和目录的 PDF，确认默认项目名并完成一次重命名；
5. 离开页面或退出 App，再次进入后从保存步骤继续；
6. 确认章节、覆盖深度、难度比例和样卡；
7. 正式生成卡片，离开生成页后从“制卡任务”区域查看进度；
8. 生成成功后牌组一次性出现全部结果；
9. 将项目设为当前学习项目，选择新卡章节范围和每日学习量；
10. 从首页今日目标进入，先处理到期卡，再学习新卡；
11. 使用四档评级并确认中断恢复、重复提交不重复计数；
12. 查看牌组和统计页真实更新；
13. 对一张来源仍可用的 AI 卡片执行重新生成，预览后替换，并确认该卡重新进入学习排程；
14. 编辑一张卡片；删除一张卡片，重启 App 后仍在 10 秒窗口内完成撤销；
15. 退出并重新登录，确认资料、项目、任务、牌组、学习时区、学习进度和统计仍存在。

任一步依赖 Mock、硬编码、手动改数据库或开发者菜单才能完成，均视为主链路未通过。

## 4. 错误与恢复验收

### V25-REL-FR-04 必验失败场景

至少验证：

- 会话失效：进入登录页，重新登录后数据和任务仍在；
- 网络中断：当前输入和项目步骤保留，恢复网络后可重试；
- PDF 无文本层或无目录：展示真实失败，不进入伪章节或生成流程；
- DeepSeek API Key 未设置、无效或余额不足：保留配置并引导设置；
- 制卡整体失败：牌组不出现部分卡片，点击重新生成无需重新上传或重配；
- 制卡返回 0 张有效卡片：任务按整体失败处理，不显示“已完成，共生成 0 张”；
- 失败任务重试：创建有关联的新任务，原失败任务和失败原因仍可追溯；
- 删除保护：任务引用的项目、章节或目标牌组在活跃阶段不可删除，且不会留下孤立任务或部分卡片；
- App 在解析、样卡确认、生成、学习中被关闭：重新进入后恢复到可解释状态；
- 单卡 AI 重写失败或取消：原卡内容、复习状态和历史记录不变；
- 单卡删除：离线请求不伪成功；页面切换、后台和 App 重启后在剩余窗口内仍可撤销；
- 重复点击或网络重试：不产生重复项目、任务、卡片或复习事件；
- 设备时区与账号学习时区不同：未经用户确认不重置今日计划或周统计；
- 统计暂时无法刷新：保留旧数据并标记未更新，不显示伪最新值。

## 5. 性能与稳定性要求

### V25-REL-FR-05 统一验收基线

性能验收必须在报告中记录目标设备、Android 版本、网络类型和测试账号数据量，至少使用：

- 20 个学习项目；
- 50 个牌组；
- 最大单牌组 1,000 张卡片；
- 账号累计 10,000 条复习事件；
- 一个正在后台正式生成的制卡任务。

可使用受控验收夹具通过正式接口构造上述真实持久化数据，但不得用前端 Mock 或内存假数据代替。AI 生成总耗时
受 PDF、模型和网络影响，不承诺固定完成秒数，但后台执行不得阻塞前台导航。

### V25-REL-FR-06 用户可感知性能

- 在已记录的目标设备上连续执行至少 20 次冷启动，从点击图标到首页可交互的 P95 不超过 3 秒；
- 页面切换、翻卡、打开弹窗和本地筛选等无需等待网络的操作，每类至少采样 20 次，P95 可见反馈不超过 500 毫秒；
- 需要网络的主要操作在 500 毫秒内未得到结果时，必须展示加载、后台任务或可重试状态，不出现无反应按钮；
- 服务端数据已返回后，1,000 张卡片牌组的首屏内容在 2 秒内可见，连续滚动、返回和筛选无 ANR、崩溃或持续 2 秒以上的主线程冻结；
- 生成、同步或统计刷新期间，首页、项目、牌组、设置之间的导航仍可操作。

### V25-REL-FR-07 稳定性与恢复

- 同一 Release 主链路连续执行两次，不因上一次残留状态产生崩溃、重复数据或错误跳转；
- 在目标设备连续执行 30 分钟“前后台切换、学习评级、列表滚动、统计刷新和任务查看”混合操作，
  不出现崩溃、ANR、无法解释的空白页或永久加载；
- 系统回收 App 后重新进入，服务端已确认状态可以恢复；本地尚未确认的写入不得显示为云端成功；
- 无网络时允许进入已有缓存的基本页面，所有不可用写操作必须明确失败或待用户重试；
- 性能门槛的计时点、采样方式和原始结果写入验收报告；缓存、分页和重试实现方案由 Architecture 定义。

## 6. 模块独立验收矩阵

| 模块 | 独立验收入口 | 通过门槛 |
| --- | --- | --- |
| 账号与个人主页 | 首页头像 → 个人主页 | 真实资料、Moods 头像、只读邮箱、跨设备保存、正确退出 |
| PDF 与制卡 | 学习页 → 制卡任务 | 自动保存、跨设备恢复、完整成功/失败、关联重试、多任务、AI 质量 |
| 牌组与卡片 | 牌组列表和详情 | 真实数据、编辑、单卡 AI 重写、10 秒撤销、高影响删除确认 |
| 学习与复习 | 首页今日目标 | 当前项目、到期优先、新卡补足、四档评级、自由刷题 |
| 进度与统计 | 统计页 | 真实数据、正确口径、空态、刷新与跨设备一致 |
| 设置 | 设置页 | 云端默认值、API Key 安全、主题、Release 无 Debug 入口 |

模块独立验收允许并行，但任何模块的默认 P0 要求仍为 `TODO`、仅 Mock 可用或存在阻断时，不得发布 V2.5。

## 7. APK 交付证据

正式验收报告至少记录：

- APK 绝对路径、文件大小和 SHA-256；
- `versionName`、`versionCode`、构建类型和签名校验结果；
- 构建时间和对应 Git commit/工作区状态；
- 目标设备型号、Android 版本、安装/升级结果；
- 各模块验收结果与失败证据；
- 主链路执行结果；
- 第 5 节性能测试的原始样本、P95 计算和 30 分钟稳定性结果；
- 三种覆盖深度的 AI 制卡夹具、人工审查记录及不通过样例；
- 尚未完成或被明确排除的事项。

只有文件存在不能证明 Release 完成；旧 APK、Debug APK、未签名 APK 或未在目标设备运行的 APK 均不得标为
V2.5 正式交付。

## 8. 最终验收标准

### V25-REL-AC-01 构建与安装

- 生成签名的 `releases/app-release.apk`，版本为 2.5.0 且版本号可升级；
- APK 可在目标设备冷安装并启动；普通用户不能修改正式服务器地址；
- APK 不依赖开发机、Mock 服务或在线头像服务。

### V25-REL-AC-02 Release 真实性

- 内置演示牌组、Mock 数据、Debug/测试入口、死按钮和占位页均不可见；
- 首页和统计页在空账号及有数据账号下均展示真实状态；
- 所有可见主操作均真实成功或返回真实错误。

### V25-REL-AC-03 端到端闭环

- 第 3 节主链路在 Release APK 和正式后端上完整通过；
- 第 4 节失败与恢复场景通过；
- 重复执行不产生重复资源或复习记录；
- 跨退出、跨页面和跨设备恢复符合各模块 PRD。

### V25-REL-AC-04 性能与稳定性

- 在 V25-REL-FR-05 基线账号和已记录目标设备上达到 V25-REL-FR-06 全部时间门槛；
- 30 分钟稳定性验收无崩溃、ANR、永久加载或伪成功；
- 后台生成期间前台核心导航和学习流程保持可用。

### V25-REL-AC-05 证据边界

- 验收报告包含第 7 节证据；
- 未通过项明确标记，不能用文档完成、测试名称或旧 APK 代替；
- 只有所有模块的默认 P0 要求、跨模块主链路、性能与稳定性门槛均通过后，V2.5 才可标记为正式发布。
